Workspace integration

Shifter uses the signed-in account’s existing API key to discover accessible personal and team workspaces. Gateway credentials, targets and traffic usage belong to the selected membership.

API contract

  • GET /api/v1/user/memberships?workspaces=all and GET /api/v1/user/proxy-config?workspaces=all opt into all accessible workspaces. Usage remains GET /api/v1/user/usage.
  • User API requests send the same key in both Authorization: Bearer and X-Api-Key. The existing OS secure-storage flow remains in use; no new API keys are embedded.
  • Plans, usage and credentials join by plan hash. A membership’s workspace falls back to proxy-config metadata. The catalog retains empty workspaces and merges workspace metadata from memberships.
  • Proxy credentials refresh before connecting. Switching memberships disconnects the previous tunnel. A catalog refresh that removes the selected plan stops its connection and clears the saved selection. Late catalog responses cannot repopulate a signed-out session.

Interface behavior

  • Personal appears first, then teams alphabetically. Phone sheets and tablet/desktop lists share the workspace grouping and empty-workspace states.
  • Personal-only and older responses retain the ungrouped layout. API product names remain unchanged. Mixed legacy responses do not hide plans without workspace metadata.
  • The selected team appears beside the plan name, with an explanation that traffic uses that workspace’s plan and wallet. Long names wrap in group headings and have tooltips in compact plan headers.
  • Owner, viewer, billing and admin roles can connect. Viewer and billing roles receive “Open in panel” instead of “Renew” for inactive plans.

The regression suites cover exact opt-in and headers, team Residential and ISP credentials for all four roles, usage mapping, remembered selection, membership switching, revoked access, stale responses, legacy and personal-only responses, and empty teams. Layout tests cover 280×653, 320×568, 393×852, 600×800, 768×1024, 1024×768, 1440×900, 1024×480 and 844×390, plus 1.3× text at 320px.

API and proxy tests use local fixtures. Production workspace deployment and a live team account require separate verification; successful local tests do not establish backend deployment status.
